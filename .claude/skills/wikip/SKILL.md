# wikip

Turn one source document into one wiki page within a corpus wiki, plus typed edges in a knowledge graph that connects the page to existing ones. Pages are document-centric (one paper = one page); the graph emerges from typed `[[wiki-link]]` relations between pages.

## Inputs

- **source-dir** (required) — a document bundle. Detect type by file presence:
  - `raw/structure.json` present → arxiv-fetch output (read `raw/sections/*.tex` per `raw/structure.json`, plus `raw/arxiv_meta.json`).
  - `booklet.md` present → video-to-booklet output (read `booklet.md` plus the video's `chapters.json` if present).
  - `content.md` + `metadata.json` present → pdf-extract output.
- **wiki-dir** (required) — corpus wiki directory, e.g. `wiki/`. Initialise first if missing.

## Workflow

1. **Initialise wiki/ if needed**: `uv run python3 .claude/skills/wikip/scripts/init.py "<wiki-dir>"`. Creates `pages/`, `graph.json`, `_schema.json` (default predicate vocabulary), `index.md` stub.
2. **Survey the corpus**: list `<wiki-dir>/pages/`, read `graph.json`, read `_schema.json`. You need this to (a) know which slugs are valid `[[wiki-link]]` targets and (b) which predicates are allowed.
3. **Detect source type and read it**: load the source content per the rules above.
4. **Plan the page** before writing:
   - **TL;DR** — 3–5 sentences.
   - **Why it matters** — one paragraph.
   - **Key claims & contributions** — bulleted, with source-section refs where useful.
   - **Methodology / approach** — what the paper actually does.
   - **Results** — if applicable.
   - **Connections** — for each existing page that this document relates to, decide on a predicate from `_schema.json`. Skip predicates that don't apply; don't force connections.
   - **Open questions** — what the paper leaves unanswered.
5. **Write `<wiki-dir>/pages/<slug>.md`** in Obsidian flavour. See [REFERENCE.md](REFERENCE.md) for the page schema. Slug = source-dir basename (e.g., `arxiv-2003.02320`, `<video-id>`, `<pdf-slug>`).
6. **Append edges to `graph.json`**: for each connection in the page, add `{"from": "<this-slug>", "to": "<other-slug>", "predicate": "<from-schema>", "context": "<one-line rationale>"}`. Only use predicates listed in `_schema.json`.
7. **Validate**: `uv run python3 .claude/skills/wikip/scripts/validate.py "<wiki-dir>"`. Reports broken `[[wiki-links]]`, edges referencing missing pages, predicates not in the schema, and orphan pages. Regenerates `index.md`. Fix issues before finishing.
8. **Report** to the user: page written, edges added, any orphans/warnings.

## Output structure

```
<wiki-dir>/
  pages/
    arxiv-2003.02320.md       paper page (Obsidian: frontmatter + body + [[wiki-links]])
    <video-id>.md             video booklet page
    ...
  graph.json                   {nodes: [...], edges: [{from, to, predicate, context}]}
  _schema.json                 {predicates: {<name>: <description>, ...}}
  index.md                     auto-generated TOC, regenerated by validate.py
```

## Predicate vocabulary

The default `_schema.json` ships with ten predicates: `cites`, `extends`, `compares-with`, `criticizes`, `formalizes`, `applies`, `surveys`, `motivates`, `disambiguates`, `same-topic`. See [REFERENCE.md](REFERENCE.md) for the precise meaning of each. The user can edit `_schema.json` to add or refine predicates; new predicates should describe relations between *pages*, not between concepts within a page.

## Merging two wikis

To combine corpora (e.g., a "KG papers" wiki and an "embedding papers" wiki into one):
```bash
uv run python3 .claude/skills/wikip/scripts/merge.py <source-wiki> --into <target-wiki>
```
Handles slug clashes via `--on-conflict={skip,replace,rename}`. Unions `graph.json`. Reconciles `_schema.json` — errors out if predicate definitions diverge so the user resolves explicitly.

## Idempotency

- **Page rewriting**: if `pages/<slug>.md` already exists, ask the user before overwriting. Re-ingesting after the source updates is fine — just confirm.
- **Graph edges**: are keyed by `from` slug. Re-running on the same source *replaces* that source's edges in `graph.json` (atomic per source), so re-ingesting after edits doesn't accumulate duplicates.

## Notes

- Pages are document-centric, not concept-centric — one source document = one page. Concepts live in frontmatter `concepts:` (an array of free-text tags) and in bold within the body. A future `wiki/concepts/` view could be derived from frontmatter aggregation.
- This skill does NOT resolve citations. Bibliography lookup against `raw/*.bib` (arxiv-fetch) is a downstream concern.
- See [REFERENCE.md](REFERENCE.md) for page schema, predicate semantics with examples, and merge details.
